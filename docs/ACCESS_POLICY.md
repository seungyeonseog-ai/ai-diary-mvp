## 첫 묶음: 기간·권한 기반

- account_access: 기존 User의 trial_started_at 우선, 없으면 registered_at을 복사. 날짜를 포함한 7일째가 끝나는 자정에 만료. 두 시각 모두 없으면 임의 체험 지급하지 않음.
- access_changes: 계정/요청ID별 이력. 선택2개3조합·전체3개 슈퍼패스·무료 권한 정의. 활성 체험은 세 기능 제공.
- 패스 부여는 신뢰된 서버 내부 함수만 사용. 사용자 임의 종료일로 무료 유료권한을 발급하는 HTTP API는 제공하지 않음. 가격·결제주기·수단·정산은 아직 미확정.
- 기간 중 기능 변경은 원래 종료일 유지. 해지는 기간말까지 기능 유지. 권한 만료와 기존 결과 열람은 분리.
- 신규가입에서 체험 기간을 같은 트랜잭션에 기록. 앱 시작 전 스키마 이행 여부 확인.

## 이행·검증

UTF-8 환경 및 저장소 루트에서 기존 가상환경 Python 사용:

```
python -B -m unittest tests.test_access_policy -v
python -B -m tools.migrate_access --database .local-check/test.db --verify-copy
python -B -m tools.migrate_access --database .local-check/test.db
```

- 격리 검사5개 PASS: 자정 직전/정각/시작전, 기존 시작/불명 가입일, 패스 조합/변경/해지/만료/계정격리, 잘못된 부여/중복·충돌 ID, 백업·전체기존값보존·재실행.
- 운영 DB 복사본: 24개 계정, 기존 모든 테이블 값 해시 일치, 재실행 안전성 PASS. 원문은 출력하지 않음.
- 실제 DB 온라인 백업 `.local-check/access-backup-20261103-214843-699330.db` 후 추가형 이행 완료. 기존 User·대화·일기·사용량 변경 없음.
- 이 묶음만으로 새 정책 화면/서버 사용량·예약 권한이 완성된 것은 아님. 실제 AI 호출0. 구독/이용권 페이지는 3번 후속.

복구는 서비스 정지·현재 자료 별도 보존 후 진행해야 하며, 이 문서는 사용자 DB를 자동으로 되돌리는 명령을 제공하지 않는다. 신규 앱·예약 작업이 만든 자료가 있는 백업을 임의 덮어쓰지 않는다.
