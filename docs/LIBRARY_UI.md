# 서재·저장 일기 UI — 작업 5

## 화면과 읽기 범위

- `/library`: 본인 `saved` 일기 최신 5권. 왼쪽은 이전 5권, 오른쪽은 최신 방향이며 최신 페이지에서 비활성. 첫 페이지의 부족한 자리는 내일부터의 미래 잠금, 오래된 마지막 페이지의 부족한 자리는 날짜 없는 빈자리다.
- `/library?view=calendar|list&month=YYYY-MM&page=N`: 서버 KST 현재 월이 기본. 달력은 해당 월 전체 저장 일기의 날짜/ID/제목, 목록은 5개씩 조회한다. 달력/목록 전환은 선택 월을 보존한다. 미래 달 선택은 서버에서도 거부한다.
- `/diary/{id}?return=...`: 기존 일기 결과 UI를 재사용한다. 조회만으로 새 Writing이나 생성 요청을 만들지 않는다. 제목/본문 편집은 같은 saved 행을 갱신한다. 사진은 본인 인증 후 조회하고 3장/장당20MiB 제한을 유지한다.
- 상세의 복귀 링크는 허용한 `/library` 경로/월/보기/페이지로만 이동한다. 로그인 만료 후에도 허용한 내부 경로로 복귀한다.
- 과거 일기 폐기는 목록으로 복귀하고 과거 날짜 재작성 기능을 제공하지 않는다. 오늘 일기 폐기는 `/space`로 이동한다. 실제 폐기 결과의 서버 날짜 판정을 사용하므로 확인창 도중 자정이 지나도 과거 기록을 오늘 것으로 재생성하지 않는다.
- 폐기 성공 후 busy 상태를 해제해 beforeunload 경고가 자동 이동을 막지 않도록 한다. 원본 ChatMessage/장기 기억용 자료는 삭제하지 않는다.

## API와 자료 호환

- 인증 필수 GET `/library-data/shelf?page=N`, GET `/library-data/month?month=YYYY-MM&page=N`.
- 계정/저장 상태/실제 날짜로 서버 필터링하며 초안·폐기·미래 타임스탬프는 진열하지 않는다. 기존 제목 없는 일기는 날짜 제목으로 표시한다. 마지막 페이지를 넘는 요청은 실제 마지막 페이지로 보정한다.
- 달력 전체 날짜 표시는 목록 페이지에 제한받지 않는다. 같은 날짜에 기존 일기가 여러 개 있으면 선택창을 제공한다.
- 기존 사진 BLOB은 읽기 모델에서 불러오지 않고 본인 전용 URL만 제공한다. 프론트는 인증 요청으로 blob을 받아 표시하고 화면 이동 시 URL을 해제한다.
- 기존 `/mypage_edit?tab=study`는 새 서재로 이동한다. `legacy=1&panel=encourage|weekly`는 각각 기존 읽기 패널을 직접 연다. 신규 화면/JS/CSS는 5a 버전을 사용한다.
- DB 컬럼 변경/마이그레이션 없음. 3번에서 만든 diary_reports의 state/title/version과 기존 timestamp, DiaryPhoto를 사용한다.

## 단계 경계

서재 아래 응원 도착 카드에는 본문 미리보기를 넣지 않는다. 주간 썸네일은 기존 조회 자료의 감정 점수 합계를 실제 날짜 순서로 그리며, 없는 날의 가짜 점수를 추가하지 않는다. 문자열 점수는 거부하고 재조회 안내를 제공한다.

응원/주간 상세의 새 UI와 생성 규칙은 각각 6/7번이다. 하루 두 요약 점검·응원 보관/만료·서재 숫자 알림의 서버 확인 처리는 6번에 남아 있다. 현재 3분 요약/기존 주간 생성 로직을 이번 단계에서 바꾸지 않는다.
