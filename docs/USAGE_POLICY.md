# 묶음2 — 대화 사용량·성공 차감·예약·재시도

2026-11-03 KST. 묶음1 완료 코드 d84645b에 사용량 관련 세 함수만 더해 분리 검증했다.

## 범위와 동작

- 기본은 작성별1회, 추가는 계정별 KST하루2회. 입력·전송·클릭·일기 생성·저장은 대화 사용량으로 확정하지 않는다.
- 성공은 답변 메시지와 작업 succeeded 상태가 DB에 커밋된 시점이다. 처리 중에는 슬롯을 예약하고 실패·취소하면 예약을 해제한다.
- failed/cancelled는 성공 횟수에 포함하지 않는다. 오늘의 추가 사용량과 현재 작성의 기본 사용량만 해당 계정에서 조회한다.
- 동일 요청 재전송은 저장된 결과를 재사용한다. 생성 결과는 있으나 저장이 실패했다면 같은 요청 재시도에서 AI를 다시 호출하지 않는다.
- 재시도마다 현재 권한·잔여 횟수를 재판정한다. 그 사이 기본을 다른 성공 요청에 썼다면 추가를 사용하고, 추가도 모두 썼다면 AI 호출 전에 차단한다.
- 계정 잠금 트랜잭션과 요청 ID·lease token으로 동시 요청을 제한한다. lease를 갱신한 재시도 이후 이전 토큰의 늦은 완료는 저장하지 않는다.
- 자정을 넘긴 이전 날짜의 늦은 대화 완료는 실패로 처리하고 새 날짜의 횟수를 차감하지 않는다. 원본과 이미 생성한 결과는 기록에 보존한다. 다음 날짜에서 이전 작업을 자동 재차감하지 않는다.
- 기존 API 필드는 유지하며 성공/예약 구분 필드를 추가한다. 이번 묶음의 프론트 파일 버전은 그대로9b2다.

| 조회 필드 | 의미 |
| - | - |
| base_used | 현재 작성에서 성공한 기본 사용 여부(0/1) |
| base_reserved | 처리 중인 기본 예약 여부(0/1) |
| base_remaining | 성공·예약을 제외한 기본 잔여 |
| extra_used | 해당 계정·날짜의 성공 추가 사용 수 |
| extra_reserved | 해당 계정·날짜의 처리 중 추가 예약 수 |
| extra_remaining | 권한이 있을 때 성공·예약을 제외한 추가 잔여 |

일기 생성 후 입력 허용·새 버튼/전등 디자인은3번, 폐기 화면·안내 변경은4번 후속이다. 기존 폐기 동작은 사용량 공유·예약 해제 회귀 검사를 위해서만 실행했다. 유료 권한·결제는 제외한다.
