# 4번 — 홈·대화·일기 화면

2026-11-02. 3번 기반 커밋 `ce31ce7` 위에서 구현했다. 서재 전체 개편은5번, 요약/응원 교체는6번, 주간3탭은7번이다.

## 화면과 자산

- `/`: 시안의 밝은 홈, 로그인 표시·입장 안내. `/account/me`로 실제 로그인 유효성을 확인하고 만료된 공개홈 세션은 비로그인으로 표시한다.
- `/login`: 기존 로그인 API/아이디 저장을 재사용한다. `next=/space`만 허용해 입장 후 복귀하며 임의 외부 복귀 URL은 사용하지 않는다. 회원가입 로직은 기존대로다.
- `/space`: 홈 탭 기본 선택, 여러 사용자 말풍선·전등·AI의 완성 말풍선·일기 확인/대기·제목/본문 결과·수정/사진/폐기/저장. AI/사용자 이름표는 제거했다.
- 사이드바 서재는 임시로 `/mypage_edit?tab=study`의 기존 열람 화면을 연결한다. 새 작성으로 돌아가는 링크를 제공하고 구형 작성 탭은 이 연결에서 숨긴다. 책장·달력·목록의 새 UI 완료를 뜻하지 않는다.
- 텃밭·별자리는 준비 중 안내. 계정/설정 버튼에서 계정 정보·홈페이지·로그아웃을 제공한다. 응원 시각 설정의 새 화면은6번 범위다.
- `ui_base.html`, `space-ui.css`, `static/js/space/*`로 기존 스타일/JS와 분리한다. 새 HTML은 no-store, CSS/모듈 URL은 버전 식별자를 사용한다. 구형 템플릿·JS는 보존한다.
- 준비한 PNG4종을 `static/images/space`로 복사했다. 원본 편집 없이 해시를 확인했고 manifest.json에 남겼다. 책·서재·편지 자산은 후속 단계에서 사용한다. 잠금·버튼·탭·날짜·아이콘은 코드 요소다.

## 전등과 스트림

1. 사용자 입력은 `/writing/{id}/messages`에서 원본으로 저장한다. Enter는 제출, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 제출하지 않는다.
2. 전등은 미제출 입력 묶음을 한 번 제출한다. 입력창에 남은 문장도 먼저 저장한다. 기본/추가 한도와 실패/진행 상태는 서버 기준으로 표시한다.
3. 새 `/writing/{id}/response_stream`은 `bubble`/`saved`/`error` SSE다. JSON 문자열이 완성된 경계만 전송하므로 단어 청크를 말풍선으로 잘라 표시하지 않는다. 쉼표·이스케이프·분할 유니코드를 decoder로 처리한다.
4. 첫 완성 말풍선은 다음 말풍선/전체 응답 종료 전에 표시된다. 저장까지 완료해야 일기 생성 확인창을 띄운다. 실패한 미저장 말풍선은 정상 기록으로 남기지 않는다.
5. 새 스트림도 기존 하이브리드 검색/버킷 선별을 재사용하고 조회된 요약은 본인 소유권을 다시 확인한다. 현재 작성의 이전 대화는 별도 맥락으로 제공한다. 검색이 실패하면 원본 입력으로 답하고 실패 유형만 기록한다. 일기 생성에는 이 맥락을 넣지 않는다.
6. 구형 `/chat/response_stream`의 일반텍스트/SSE 협상과 새 `/writing/.../generate` JSON 계약은 유지한다. 새 작성 이력이 있는 계정의 구형 생성/입력 API는409로 새 화면을 안내해 한도·입력범위 우회를 막고 조회는 유지한다.

## 일기·복원·실패

- 일기 확인 → 작성 중 캐릭터 → 결과 자동 이동. 추가 완료 모달은 없다. 취소하면 추가 기회가 있는 범위에서 대화하고, 입력을 더하지 않았으면 기존 이야기를 일기로 만들 수 있다.
- 일기는 같은 레코드의 제목/본문을 수정한다. 수정 중에는 사진·최종 저장을 잠그고 수정 완료 뒤 동일 결과 UI로 돌아온다. 저장한 일기도 현재 결과 화면에 유지한다.
- 수정 원문과 미전송 입력은 계정/작성별 sessionStorage로 임시 복원한다. 로그아웃/계정 변경 때 지우고, 응답이 늦게 도착해도 다른 계정에 표시하지 않는다. 파일 자체의 브라우저 임시 보관은 새로고침을 넘겨 보장하지 않으므로 업로드 실패 파일/진행 작업에는 이탈 경고가 남는다.
- 생성 실패: 원본 보존, 서버에 남은 같은 request_id로 재시도. 진행 중 작업은 상태 조회로 복원하며 오래된 lease가 지나야 재시도한다. 실패한 일기 요청이 있는 동안 원본 입력 변경을 서버도 차단한다.
- 저장 실패: 초안과 수정 내용 보존. 생성 API를 부르지 않고 저장만 재시도한다. 서버 저장 후 응답 유실도 같은 일기 행/버전으로 확인한다.
- 사진:3장·장당20MiB, 본인 인증 blob 조회. 해당 파일만 재시도/선택 해제, 다른 사진/본문 유지, AI 전송 없음. 저장 완료 후에도 사진/편집/폐기가 가능하다.
- 버전 충돌: 현재 수정은 유지하고 최신 내용 확인 또는 명시적으로 현재 수정 반영을 선택한다.
- 폐기: 확인 모달 후 새 작성. 원본 채팅은 보존하고 새 일기 원본에는 섞지 않는다. 과거 일기 처리 UI는5번에서 연결한다.
- 날짜가 바뀌면 서버 시각/원본 날짜를 확인해 오늘 작성으로 전환한다. 이미 생성된 전날 초안은 실제 날짜를 유지한 채 저장/편집한다.
- 기존 WebSocket 인증 흐름·개인 알림 캐시/서버 복원 연결을 유지한다. 서재 숫자 배지/진입 확인의 최종 영속 연동은5/6번에 남는다.

## 일기 문체 검증에서 수정한 사항

최초 실제 일기 결과가 원문의 어미만 바꾼 짧은 재서술에 가까워 사용자 지적을 받았다. UI가 원문을 잘못 붙인 문제가 아니라 실제 AI 결과였다. 새 작성용 프롬프트를 `DiaryPromptService.generate_writing_prompt`로 분리하고, 상황→감정 변화→하루에 남은 마음의 회고, 문단 구성, 피할/원하는 문체 예시, 원문/예시 분리를 명시했다. 내용이 빈약할 때 길이를 강제하거나 없는 사건/감정/다짐을 만들지 않도록 했다. [OpenAI 공식 프롬프트 가이드](https://developers.openai.com/api/docs/guides/prompt-engineering)의 명확한 지침/예시/맥락 분리 방식을 참고했다.

사용자 추가 승인으로 일기1회만 재검증했고, 사용자가 직접 입력한 결과의 품질을 수용했다. 입력 조건이 최초 합성 비교 입력과 달라졌으므로 프롬프트 단독 효과의 통제된 A/B 평가로 주장하지 않는다. 실제 입력/일기 원문은 작업 기록에 복사하지 않았다. 추가 API 자동 재시도·품질점수에 따른 유료 재생성은 구현하지 않았다.
